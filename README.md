# 换线清场与首件放行

本项目记录包装产线换产品时的清场证据、设备校验和首件结果。检查范围由产品转换关系确定，区域证据、人员签字和机器回执都只能追加。

`domain_contract.json` 描述换线、检查项和开线令牌状态。离线终端消息带设备内序号，令牌始终绑定产线、产品、配方版本和有效期。

## 结构

- `app/catalog.py` — 区域清单、产品目录、设备回执样例的加载（`data/` 下的 JSON 定义了必须核对的对象）。
- `app/matrix.py` — 产品转换矩阵：按致敏原转换关系给出风险等级与检查范围，按版本生效；工单在准备时点冻结版本与范围。
- `app/changeover.py` — 换线工单聚合：扫码/计量/异常声明/机器回执入账，人工确认，残留触发重新清洁并使相关区域签字失效（不连带无关区域）。
- `app/service.py` — 工单生命周期、开线条件核验（清场通过 + 模具与程序一致 + 首件获批）、开线令牌的签发/核销/吊销。
- `app/report.py` — 批次页面：还原每个区域的证据、失效重签原因、首件数据和最终令牌去向。

## 关键规则

- 机器回执与人工确认只追加；离线终端补传按设备内序号幂等去重，有效证据按发生时间取最新，补传的旧记录不覆盖后来完成的检查。
- 清场结论使用准备时点版本的转换矩阵。
- 跨岗代签、旧标签冒充本批、重复扫描、令牌过期/错配均被明确拒绝（见 `app/errors.py`）。

## 运行检查

```bash
python3 -m unittest discover -s tests -v
```

`tests/test_acceptance.py` 是一轮高风险换线（含致敏原 → 普通产品）的完整验收时间线；`tests/test_rules.py` 覆盖各条领域规则。
